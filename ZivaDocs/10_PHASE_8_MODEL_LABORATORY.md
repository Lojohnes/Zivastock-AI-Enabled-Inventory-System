# Phase 8 — AI Model Laboratory, Scenarios and Validation Evidence

**Status:** Implemented incrementally  
**Git status:** Uncommitted; no GitHub repository or commit created

## Purpose

Phase 8 adds research-facing controls around the intelligence platform:

- Model registry visibility
- Evaluation metric review
- Forecast/scenario visualisation
- Recommendation outcome analytics
- Validation evidence capture foundation

## Backend additions

### Model registry endpoint

Added:

```text
GET /api/v1/anomalies/models
```

The endpoint returns registered model versions, including:

- Algorithm
- Version
- Dataset version
- Feature-set version
- Features
- Hyperparameters
- Evaluation metrics
- Status
- Creation date

This supports experiment reproducibility and model-lifecycle review.

### Recommendation outcome analytics

Added:

```text
GET /api/v1/recommendations/outcomes/summary
```

The response includes:

- Total recommendations
- Pending count
- Approved count
- Rejected count
- Overridden count
- Completed count
- Successful outcomes
- Partial outcomes
- Failed outcomes
- Completion rate
- Success rate

These measures provide a foundation for evaluating recommendation usefulness and acceptance.

## Model Laboratory interface

The page displays:

- Registered model count
- Completed recommendation count
- Recommendation success rate
- Pending decisions
- Model algorithms
- Model versions
- Model status
- Evaluation metrics
- Model registry details

When the registry is empty, the interface explicitly explains that models must be registered through the experiment endpoints rather than displaying fabricated results.

## What-if scenario controls

The interface allows users to change:

- Current stock
- Predicted daily demand
- Safety stock
- Scenario horizon
- Demand change percentage
- Supplier delay days

The scenario calls:

```text
POST /api/v1/forecast/scenario
```

The response displays:

- Stockout risk
- Days until stockout
- Ending inventory after the scenario horizon
- A stock projection chart

The values are generated by the existing deterministic scenario service.

## Forecast visualisation

The initial visualisation presents current stock and scenario-horizon stock using Recharts. It is intentionally based on returned scenario calculations and does not invent historical values.

A later iteration can add persisted forecast time-series charts from `forecast_results`.

## Recommendation outcome analytics

The page displays:

- Approved recommendations
- Rejected recommendations
- Overridden recommendations
- Successful outcomes
- Pending decisions
- Completion and success percentages

This creates the foundation for research measures such as:

- Recommendation acceptance
- Override frequency
- Outcome success rate
- Human trust and usefulness evaluation

## Research relevance

Phase 8 supports the dissertation's reproducibility and validation requirements by making model metadata, evaluation metrics, scenarios and recommendation outcomes visible to researchers and management users.

It supports the progression:

```text
Experiment
    → Evaluate
    → Compare
    → Simulate

```

## Limitations

1. Model training remains API-driven rather than fully orchestrated from the browser.
2. Forecast charts currently focus on scenario projections; full historical forecast charts are a later enhancement.
3. Validation evidence is represented through metrics and outcome summaries but does not yet provide a dedicated experiment-report export.
4. The model laboratory requires persisted model versions to display meaningful registry data.
5. The current frontend build has a large JavaScript bundle that should be code-split before production deployment.
